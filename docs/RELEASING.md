# Releasing the Android APK

The app isn't on Google Play. Each GitHub release gets a signed APK attached to
it by [`.github/workflows/release-apk.yml`](../.github/workflows/release-apk.yml),
which people download and install by hand.

## One-time setup: the signing key

Android only installs an update over an existing install when both APKs are
signed with the same key. **If the keystore is lost, every user has to
uninstall (and lose their progress) to get the next version.** Keep a backup of
the `.jks` file and its passwords somewhere outside the repo, such as a
password manager.

1. Generate the keystore (needs a JDK; in WSL: `sudo apt install openjdk-17-jre-headless`):

   ```bash
   keytool -genkeypair -v -keystore turkolinguo-release.jks -alias turkolinguo \
     -keyalg RSA -keysize 4096 -validity 10000
   ```

   `*.jks` is git-ignored in `app/`, but keep the file outside the repo anyway.

2. Encode it for GitHub:

   ```bash
   base64 -w0 turkolinguo-release.jks > keystore.b64
   ```

3. In the GitHub repo, open Settings → Secrets and variables → Actions and add:

   | Secret                      | Value                                        |
   | --------------------------- | -------------------------------------------- |
   | `ANDROID_KEYSTORE_BASE64`   | contents of `keystore.b64`                   |
   | `ANDROID_KEYSTORE_PASSWORD` | the store password you chose                 |
   | `ANDROID_KEY_ALIAS`         | `turkolinguo` (the `-alias` above)           |
   | `ANDROID_KEY_PASSWORD`      | the key password (same as store if you didn't set one) |

   Then delete `keystore.b64`.

## Cutting a release

1. Make sure CI is green on the branch you release from.
2. Create a release on GitHub with a tag of the form `vX.Y.Z` (for example
   `v0.2.0`) and publish it. `gh release create v0.2.0 --generate-notes` does
   the same from a terminal.
3. The **Release APK** workflow builds `turkolinguo-v0.2.0.apk` and attaches it
   to the release, usually within 10–15 minutes.

The tag sets the version shown in Android settings (`versionName`) and the
internal `versionCode` (`major*1000000 + minor*1000 + patch`). Android refuses
to install a lower `versionCode` over a higher one, so tags must only go up.
The `version` in `app/app.json` is used only for local builds.

## Test builds

Run **Release APK** by hand from the Actions tab (Run workflow) to build an APK
from any branch without making a release. It's kept as a workflow artifact for
14 days. It keeps the `versionCode` from `app/app.json` (1), which is lower
than any release, so Android won't install it over a release build: uninstall
the release first, or use a separate test device.

## How signing is wired

`app/android/` is generated by `expo prebuild` and isn't committed. The config
plugin [`app/plugins/withReleaseSigning.js`](../app/plugins/withReleaseSigning.js)
adds a release signing config to the generated `build.gradle` that reads the
keystore from the `ANDROID_KEYSTORE_*` environment variables. Without them,
release builds fall back to the debug key, so local release builds keep working.
